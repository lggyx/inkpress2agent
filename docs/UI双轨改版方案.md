# InkPress UI 全量改版方案 v2（定案版）

> 2026-11-14 · 取代上一版（用户裁决"全做"，不再给选择题）· 本文档=设计宪法+全页面规格+工程路径

---

## 一、设计宪法（不可违反，7 轮裁决换来的）

1. **零渐变、零辉光、零玻璃、零噪点**——色与面只有实色
2. **底色永远是浅暖白**——不做黑主调、不做红主调、不做冷灰
3. **色块饱和度要高**，但同屏可见色相 ≤ 3 个（信息单元=色块，不是彩虹）
4. **375px 是设计基准**——每个页面先画手机版，桌面是宽幅延伸
5. **去博客三件套**：无时间轴列表、无侧栏、无传统顶部导航——改用 App 式底部标签栏
6. 大字优先：标题黑体 900、数据用超大数字，正文短段落
7. 动效只做三类：色块位移、数字滚动、按压反馈——不做漂浮/光效/粒子

## 二、定案视觉系统「画廊白 × 色块卡片」

| Token | 值 | 用途 |
|---|---|---|
| 底色 | `#FAF7F2` 暖白 | 全局背景 |
| 墨色 | `#1A1714` | 正文/标题 |
| 卡片白 | `#FFFFFF` | 内容卡底 |
| 色块-靛 | `#2C4A8A` | 文章/检索 |
| 色块-橙 | `#E8622C` | 进化/运行态 |
| 色块-绿 | `#2E7D5B` | 图谱/成功态 |
| 色块-黄 | `#E9A820` | 标签/高亮 |
| 色块-灰陶 | `#B9AFA3` | 中性块/禁用态 |
| 圆角 | 20px（大卡）/ 12px（chip） | 无直角锐边，无圆形头像滥用 |
| 字体 | 黑体族（PingFang/微软雅黑 900 标题） | 数字用 tabular |

**色块语法**：每个内容单元占一块实色；色相=语义（靛=文章、橙=进化、绿=图谱、黄=标签）；文字压在色块上时白字或墨字（对比度 ≥ 4.5:1）。

## 三、全局壳（"非博客"的关键一步）

- **底部标签栏（5 tab）**：今日 · 进化 · 图谱 · 发现 · 我的——App 式拇指导航，替代顶部导航
- 顶栏只剩：左侧 logo 字标 + 右侧搜索 icon，滚动即隐
- 页面切换：色块横向滑动过渡（≤300ms）

## 四、页面逐一规格（移动 375 优先，桌面延伸）

### 1. 首页「今日」——色块墙
- 顶部问候区：今天日期 + 进化状态条（一条橙色块：`RUN #4 · 采纳率 100%`，点击进面板）
- **2×2 色块矩阵**：六子系统各占一块（靛/橙/绿/黄轮换），块内=大数字+名称，点进对应功能
- **最新文章横向滑动大卡**：每篇一张 85vw 色卡（分类色），标题 22px 白字，日期与阅读数小字
- 底部「今日精选」单块：当日 SEO/GEO 精选文章
- 桌面：色块墙变 4×3 mosaic，最大 1280px 居中

### 2. 文章页
- **满幅色块题图**（38vh，分类色）：白字大标题压块 + 日期/阅读数 chip
- 白底正文（保留现有 KaTeX/排版），正文宽 100%，字号 17px
- 底部**悬浮操作条**（thumb 区）：点赞 / 分享 / AI 问答（点开即 AI 总结卡）
- GEO「核心结论」卡保留，改为**墨字白卡+左侧色条**（跟随分类色）
- 相关阅读：底部横向色块小卡
- 桌面：题图色块左置 40%，正文右 60%

### 3. 进化面板——大数字卡流
- 运行状态：满屏橙色块（运行中）或绿色块（空闲）+ 巨大数字（采纳率 72px）
- 两次对比：左右双卡（上一次 vs 最近一次），修改幅度变化用**色块高度条**呈现（29.9% vs 1.2% 一眼见高差）
- 写作记忆：白卡列表 + 左侧分类色条
- 快照回退：独立色块按钮区（灰陶底），二次确认
- 桌面：双卡并排，记忆三列

### 4. 发现（检索）
- 进入即全屏搜索：大输入框 + 历史色块 chip
- 结果流：每条=白卡+左侧色条（命中模式决定色：BM25 靛/向量绿/混合橙），高亮词黄底
- 降级态（ES 宕机）：顶部灰陶横幅明示「已降级 BM25」

### 5. 图谱
- 全屏 force 图，底改暖白，节点=分类色圆点，边细灰
- 底部抽屉：点节点滑出文章色块卡
- 桌面不变全屏

### 6. 工作台（移动）
- 对话全屏（现有 70vh 布局收成 100%），预览/微调收进底部抽屉
- 发送条 thumb 高度 ≥ 48px
- AI 回复卡保留 替换正文/追加/👍👎——按钮尺寸加大

### 7. 管理端
- 不改视觉，只把四槽/OSS 卡片改纵向单列（已是）——低优先级

## 五、AI 线（完整规格，全做）——动态生成，贴传统后端架构

**架构定调**：本项目是传统后端服务（Spring Boot + Nuxt SSR + MySQL/Redis），AI 线**绝不做静态文件**，全部走**动态服务端路由、请求时从库直出**——完全复用站点已有的动态 server routes 模式（`sitemap.xml`/`robots.txt` 已是这套模式：请求时生成、随部署域名自适应）。内容一发布，AI 线下一跳就是新的，无构建步骤、无同步脚本。

**五个动态端点**（Nuxt server routes，`Content-Type: text/markdown` / `text/plain`）：

| 路由 | 动态来源 | 更新时机 |
|---|---|---|
| `/llms.txt` | 实时聚合：文章索引（title/id/updated）+ 六子系统 + 进化指标一行（读 evolution_run 最新）+ 演示入口 | 每请求生成 + Redis 缓存 60s；发布事件主动失效 |
| `/llms-full.txt` | 全部 PUBLISHED 文章全文拼接 | 同上（缓存 300s，体量大） |
| `/ai/article/:id` | 单篇直出：`# 标题` + `> 核心结论（geo_summary 实时取）` + `content_md` 原文 + 元数据 | 请求时直出（可加 ETag=updated_at，304 免费） |
| `/ai/evolution` | evolution_run + writing_memory 实时序列化：每次运行一行（时间/采纳率/修改幅度/学到记忆条数）| 请求时直出——**AI 能读到博客怎么进化的** |
| `robots.txt` | 现有动态路由扩展：GPTBot/ClaudeBot/PerplexityBot 显式 Allow + `# see /llms.txt` | 已有模式，加几行 |

**为什么这是"有效优化"而不是新造轮子**
1. 与 `sitemap.xml` 同构——同一套 server route 模式、同一个发布自适应机制，团队（和评委读代码时）一眼看懂
2. 数据零冗余：AI 线不存任何内容副本，永远与 MySQL 中现状一致——发布/修改/回退即时反映
3. 缓存策略分层：llms.txt 60s、full 300s、article 用 ETag 协商——爬虫不压垮库，人发布不等待
4. 只读安全：AI 线全部走 `$pub` 公开读通道，不暴露任何写路径

**明确不做**：UA 分流/内容协商（同 URL 双面孔有惩罚风险）；静态构建期生成（违背动态后端现实，会引入同步脚本与陈旧数据）；现有 JSON-LD/摘要块保留（AI 线组成部分）。

**红线**：内容层 API 零改动；AI 线是纯增量路由，可随时摘除。

**内容规模现状（2026-11-14 核实）**：站点 **35 篇已发布文章**（3 个分类：算法与竞赛 19 / 开发笔记 12 / 杂记 4）——全部来自静态博客 `lggyx.github.io` 全量迁移（555 张配图并入站点静态资源，正文保留原发布日期标注），其余旧种子内容已按用户裁决清理。

## 六、工程路径（四阶段，每阶段独立可回滚）

| 阶段 | 内容 | 量 |
|---|---|---|
| P0（提交后当晚） | AI 线 MVP：llms.txt + /ai/article + /ai/evolution + robots | 后端 1 controller，~3h |
| P1 | 设计 token 落 main.css + 全局壳改造（底部 tab 栏、顶栏收敛） | ~半天 |
| P2 | 页面逐个换装：首页 → 文章页 → 进化面板 → 发现 → 图谱 → 工作台 | 每天 2 页 |
| P3 | 桌面宽幅延伸 + 管理端微调 | ~半天 |

每阶段先出预览台（demo-ui.html 流程，沿用 v4~v6 的先预览后落地纪律），**用户点头上生产，不直接改线上**。

## 七、验收标准（每页过一遍）

- [ ] 375px 宽下无横向滚动、拇指热区 ≥ 44px
- [ ] 同屏色相 ≤ 3、无渐变/辉光/玻璃/噪点（脚本扫描）
- [ ] 文字对比度 ≥ 4.5:1
- [ ] Lighthouse 移动端性能 ≥ 85
- [ ] KaTeX/图表等既有功能无回归（公式/图谱/检索三臂）
- [ ] AI 线 curl 直出 markdown，无 HTML 噪音
