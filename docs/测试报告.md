## 四、检索对比实验（RRF）

工具：`docs/perf/rrf_experiment.py`，数据：`docs/rrf-experiment-result.json`

**2026-11-14 复测**：语料扩充至 19 篇后三臂**首次全部真实执行**（此前所有 vector 臂实际回落 bm25，且 `degraded=false` 语义有歧义——该标志仅表示 ES 宕机降级，不表示能力槽回落，已在本节如实标注）：

| 查询 | bm25 有效模式/延迟 | vector 有效模式/延迟 | hybrid 有效模式/延迟 |
|---|---|---|---|
| 知识图谱 | bm25 / 93.9ms | **vector** / 112.1ms | **hybrid** / 57.9ms |
| Spring Boot | bm25 / 24.2ms | **vector** / 47.0ms | **hybrid** / 48.9ms |
| JWT 鉴权 | bm25 / 48.6ms | **vector** / 68.2ms | **hybrid** / 46.8ms |
| Redis 缓存 | bm25 / 21.4ms | **vector** / 40.1ms | **hybrid** / 69.6ms |
| Elasticsearch 检索 | bm25 / 52.7ms | **vector** / 62.6ms | **hybrid** / 70.7ms |

- **诚实口径**：本轮 vector 臂经由**确定性伪向量**（字符二元组哈希 mock 服务）驱动，仅证明"embedding 调用 → ES kNN → RRF 融合"全链路机械可用；**论文引用的语义排序数据必须配置真实 embedding Key 后重跑**（脚本已就绪，`INKPRESS_BASE` 可指定环境）。
- 配套修复：`EmbeddingService.available()` 此前误耦合到 text 能力槽（只配 embedding 时向量臂静默失效），已改为独立校验 embedding 槽。

### 7.3 本轮发现并修复的真实缺陷

| 缺陷 | 根因 | 修复 |
|---|---|---|
| **限流拒绝返回 403 空响应**（应为 429+JSON），伴随服务端 `getWriter() has already been called` 异常刷屏 | `RateLimitFilter` 拒绝路径用 `Map.of("data", null)` 组装响应——`Map.of` 不允许 null 值，触发 NPE，且此时响应已过半，错误处理级联失败 | 改为字面量 JSON 写出；复测确认第 11 次起干净返回 `429 + {"code":429,...}` |
| **只配 embedding 槽时向量臂静默失效** | `EmbeddingService.available()` 误查 text 槽（`isConfigured()`）而非 embedding 槽 | 改为 `configured(CAP_EMBEDDING)` 独立校验 |
| 压测脚本硬编码 `D:\final-work\...` 路径，任何其他检出均无法复现 | 原作者机器绝对路径落库 | 全部改为 `Path(__file__)` 相对路径；`INKPRESS_BASE`/凭据走环境变量（测试口令不再入库） |
