## 一、选题的背景和意义

### 1.1 选题背景

内容创作者目前主要依赖托管平台发布文章，例如微信公众号、知乎、掘金等。这类平台解决了分发问题，但创作者对内容本身并没有完整的控制权：排版受平台编辑器限制，数据导出渠道有限，部分内容受平台审核规则约束，个人也难以在页面上体现自己的风格。与此同时，Markdown 已经成为技术写作者的主流写作格式，创作者更希望拥有一个数据自有、样式可定制、支持 Markdown 工作流的个人站点。

博客系统本身并不新鲜。WordPress 占据了全球网站内容管理系统市场的主要份额，Ghost、Halo 等系统也提供了现代化的写作体验。但这些系统大多将 AI 能力排除在核心功能之外，或者以插件形式另行接入。2022 年底以来，以 GPT 系列为代表的大语言模型（Large Language Model, LLM）在文本生成任务上达到了可用的水平，国内智谱 GLM、DeepSeek、通义千问等模型也都开放了 API 服务，调用成本已经低到个人开发者可以承受的程度。将文本润色、摘要生成、标签推荐这类能力直接做进写作流程，对每天产出的个人创作者有实际价值，这也为博客系统的功能设计提供了新的方向。

### 1.2 选题意义

实际应用方面，本课题面向个人创作者，设计并实现一个包含文章管理、分类标签、评论互动和数据统计的博客与文章管理系统，并将大模型 API 封装为写作辅助模块。系统采用前后端分离架构部署，作者可以完全掌控自己的数据，AI 功能以"辅助"定位融入编辑器，而不是替代写作。

个人学习方面，本课题覆盖了 Java Web 开发的主要环节：Spring Boot 框架、MyBatis-Plus 持久层、MySQL 数据库设计、Redis 缓存、Spring Security 与 JWT 认证、RESTful 接口设计，以及 Vue 3 前端工程化。其中大模型 API 的接入涉及提示词设计、流式响应（SSE）转发、多服务商适配和超时降级等工程问题，这类问题在现有课程体系中较少涉及，通过本课题可以完整实践一次 AI 能力的工程化落地。

## 二、国内外研究现状

### 2.1 博客与内容管理系统

国外方面，WordPress 是目前使用最广泛的内容管理系统。根据 W3Techs 的统计，截至 2025 年，WordPress 驱动了全球约 43% 的网站，在全球内容管理系统市场中占比约 60%。WordPress 基于 PHP 与 MySQL，插件生态庞大，但其单体架构和同步加载方式在现代前端工程实践中显得偏重。Ghost 使用 Node.js 实现，主打订阅制写作，编辑体验好，但定制主题需要熟悉其模板语言。Hugo、Hexo、Jekyll 属于静态站点生成器，把 Markdown 文章在本地编译成静态页面，访问速度快、维护成本低，缺点是没有后台，评论、搜索等动态功能要依赖第三方服务。国内方面，Typecho 是轻量的 PHP 博客程序，Halo 使用 Java 开发、采用可插拔架构，近年在中文社区增长较快。

总体来看，现有系统解决了"发布"的问题，但多数项目起步较早，前端部分仍是模板渲染或混合渲染；对 AI 写作辅助的支持基本停留在插件层面，缺少与编辑器、文章元数据（摘要、标签）打通的一体化设计。

### 2.2 Web 应用开发技术

Fielding 在 2000 年的博士论文中提出 REST 架构风格，此后资源化的接口设计逐渐成为 Web 服务的主流约定。前后端分离架构下，前端通过 HTTP 接口获取 JSON 数据并自行渲染，后端只负责业务逻辑，两端的开发与部署可以独立进行。认证方面，传统的 Session 方案在集群环境下需要共享会话存储，基于 JSON Web Token（JWT，RFC 7519）的无状态认证把用户信息签名后放入令牌，服务端不保存会话状态，更适合前后端分离与横向扩展的部署形态。持久层方面，MyBatis-Plus 在 MyBatis 之上提供了通用 CRUD 与分页插件，减少了重复代码。缓存方面，Redis 以内存存储支撑热点数据的高频读取，是缓解数据库压力的常用手段。前端方面，Vue 3 的组合式 API 改变了按选项组织代码的方式，使相关逻辑可以聚合维护，配合 Vite 构建工具获得了较快的开发体验。

### 2.3 大语言模型与写作辅助应用

Vaswani 等人在 2017 年提出 Transformer 结构，以自注意力机制替代循环网络处理序列依赖，成为后续大模型的基础架构。Brown 等人在 2020 年证明，参数量足够大的语言模型可以通过上下文学习（in-context learning）在不微调的情况下完成多种文本任务。国内模型方面，智谱的 GLM 系列、DeepSeek 系列、阿里的通义千问系列均开放了 API，且大多兼容 OpenAI 的 Chat Completions 接口格式，这一格式已成为模型服务的事实标准。在写作场景中，生成式摘要可以自动提取文章要点，文本润色可以对表述进行改写优化，关键词抽取可以辅助作者打标签，这些任务都可以通过提示词（Prompt）设计直接调用通用模型完成，不需要训练专用模型。

### 2.4 现状分析小结

综上，博客系统的功能形态与技术方案已经比较成熟，可参考的实现较多；大模型 API 也已经具备了低成本接入的条件。现有工作的不足在于：将"现代前后端分离技术栈、数据自有、AI 写作辅助一体化"三者结合的轻量级系统仍然较少。本课题在这一组合方向上做设计与实现，工作量与新颖度适合本科毕业设计。

## 三、主要研究内容

### 3.1 系统功能范围

系统面向两类角色，共规划三部分功能：

**前台（访客）**：文章列表与分页浏览、文章详情（Markdown 渲染与代码高亮）、按分类/标签筛选、归档时间线、关键词搜索、评论与回复、点赞、热门文章展示。

**后台（管理员/作者）**：登录认证与权限控制、数据看板（文章量、评论量、访问趋势的可视化）、文章管理（草稿、发布、置顶）、Markdown 编辑器、分类管理、标签管理、评论审核、用户管理、操作日志查询。

**AI 写作辅助**：文章润色（流式输出，边生成边显示）、一键生成摘要、自动推荐标签。AI 模块作为独立的适配层设计，通过统一的抽象接口对接不同模型服务商。

### 3.2 拟解决的关键问题

1. **多模型服务商的统一适配**。不同厂商的 API 地址、鉴权方式和参数细节存在差异，需要设计可插拔的适配层：定义统一的对话模型接口，默认实现 OpenAI 兼容协议（覆盖 OpenAI、DeepSeek、智谱、通义千问、Moonshot Kimi 及本地 Ollama 等），更换服务商只需修改配置而不改动业务代码。
2. **流式响应的转发**。润色功能要求生成内容实时显示，后端需要将上游模型返回的 SSE 数据流逐段解析并转发给浏览器，处理断连、超时与中断。
3. **缓存与数据库的一致性**。文章浏览量、点赞数属于高频写入的数据，采用 Redis 计数、定时回写数据库的方案，需要处理回写时机与数据丢失窗口。
4. **内容安全**。Markdown 渲染为 HTML 后存在脚本注入风险，前端渲染时做 HTML 白名单净化；评论内容做转义与长度限制；接口层通过 Spring Security 做认证与基于角色的授权。

## 四、研究方法与技术路线

### 4.1 研究方法

按照软件工程的规范流程组织开发：需求分析阶段通过角色用例梳理功能边界；设计阶段完成总体架构、数据库 E-R 模型与接口定义；编码阶段采用迭代方式，先搭建框架与核心链路，再逐模块实现；测试阶段进行功能测试、接口测试与浏览器兼容性测试。文献研究贯穿全程，重点参考框架官方文档与相关论文。

### 4.2 技术路线

| 层次 | 技术选型 | 说明 |
|------|---------|------|
| 开发语言 | Java 17、JavaScript (ES2020+) | 后端/前端 |
| 后端框架 | Spring Boot 3.x、Spring Security、MyBatis-Plus | 业务框架、认证授权、持久层 |
| 数据存储 | MySQL 8.0、Redis 7.x | 关系数据、缓存与计数 |
| 认证方案 | JWT（jjwt 0.12） | 无状态令牌认证 |
| 接口文档 | Knife4j（OpenAPI 3） | 在线接口文档 |
| AI 接入 | 大模型 API（OpenAI 兼容协议），SSE 流式 | 可插拔适配层，默认智谱 GLM-4-Flash |
| 前端框架 | Vue 3 + Vite、Vue Router、Pinia | 组合式 API |
| UI 与组件 | Element Plus、Vditor、ECharts | 界面组件、Markdown 编辑、图表 |
| 部署 | Docker Compose、Nginx | 容器化部署、静态资源与反向代理 |

系统总体为前后端分离结构：Vue 前端经 Nginx 提供服务，业务请求转发至 Spring Boot 后端；后端按 Controller—Service—Mapper 三层组织；Redis 承担缓存与计数；AI 适配层封装模型调用细节，对上层暴露统一的写作辅助服务。

## 五、可行性分析

**技术可行性**：所用技术均为成熟的主流方案，官方文档与社区资料完整；AI 服务商提供免费额度的模型（如 GLM-4-Flash），接口调用无需训练模型。开发环境中 JDK 21、Maven、Node.js、Docker 均已具备，MySQL 与 Redis 可通过 Docker 容器快速部署。

**经济可行性**：开发过程全部使用开源免费软件；AI 功能依赖的大模型 API 提供免费档位，个人写作场景的调用量下几乎不产生费用；部署可使用低配置云服务器或本地环境，成本可控。

**个人能力可行性**：本人已系统学习 Java 程序设计、数据库原理、Web 应用开发、计算机网络等课程，熟悉 Maven、Git 等工具的使用，具备完成本课题所需的知识储备。
