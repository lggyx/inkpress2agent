# 结 论

经过四个月的设计与开发，InkPress 个人博客与文章管理系统已经完成了预定的全部目标。回顾整个过程，本文的主要工作可以概括为三点。

第一，完成了一个数据自有的博客系统。系统覆盖了文章管理、分类标签、评论互动、数据看板等博客核心功能，采用 Spring Boot 与 Vue 3 的主流技术栈，前后端通过 RESTful 接口协作。工程上没有停留在"能跑"：浏览量用 Redis 计数加定时回写，把高频写挡在数据库外；Markdown 渲染经过白名单净化；接口按角色鉴权，参数边界有校验。这些细节共同保证了系统的质量。

第二，把大模型能力做成了可用的功能。AI 写作辅助没有停留在演示层面：适配层屏蔽了厂商差异，切换模型只改三项配置；润色和续写用 SSE 流式输出，前端做了打字机效果和中止控制；提示词设计考虑了输出格式约束和解析容错，模型抽风时不会阻断用户的保存操作。检索实验五组查询 Top-1 全部命中，说明本地向量方案在无密钥环境下也是有效的。

第三，做了一次检索增强生成的完整实践。从向量模型选型、特征哈希实现、混合排序公式，到 RAG 四步流程和引用溯源，这条链路是论文与一般博客系统的区别所在。它回答了一个具体问题：个人博客的内容怎么被"用起来"，而不只是"存起来"。

系统当然还有不足，主要有三处。AI 功能依赖外部服务，网络波动时体验会受影响，后续可以加请求队列和重试；本地特征哈希向量无语义泛化，检索精度与商用 Embedding 有差距，语料规模上去后值得做一次量化对比实验；操作日志目前只记录管理端行为，访客侧的异常访问还没有采集。

后续如果有机会继续做，方向大概有两个。一是把语义搜索接入前台搜索框，并在检索实验基础上扩大查询集，做更系统的评测；二是把 RAG 问答从"单轮问答"扩展到"多轮对话"，结合会话历史做指代消解。这两个方向都不需要推翻现有架构，适配层和向量服务的设计已经留出了空间。
